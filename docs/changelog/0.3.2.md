# 0.3.2 Canic adoption corrections

Status: release candidate; package version remains 0.3.1 until the
maintainer-owned patch release

## Objective

Correct the Canic adoption contract and close the fresh-inactive inventory gap
without adding a second timer registry or changing the watchdog protocol.

## Runtime correction

- `reconcile_once`, `reconcile_after_completion`, and `reconcile_watchdog` now
  install fresh inactive declarations instead of returning before
  registration.
- Retained fixed declarations therefore appear in the complete canonical
  inventory and reserve capacity before application lifecycle hooks, even when
  their durable authority currently requires no wake-up.
- A focused runtime test registers all three policies inactive, observes no
  provider handles, and proves each snapshot is unregistered with no fabricated
  generation.

## Canic contract correction

- One bounded Canic custody collection may own opaque registration
  capabilities so authority-snapshot quiescence can enumerate application as
  well as framework claims. It stores no scheduling or observability state and
  does not compete with the canonical registry.
- The five dynamic built-ins use retained `Once` declarations because their
  callbacks choose explicit deadlines or retry/continuation decisions.
- Root canister-pool maintenance is the retained fixed-cadence
  `AfterCompletion` declaration. Public one-shots, public intervals, and
  lifecycle deferrals remain remove-on-stop; no Canic watchdog is introduced.
- The metrics adapter maps legacy schedule counts to committed
  `wakeups_armed`, not schedule requests, and preserves optional generation,
  armed delay, split stale roles, callback starts, and completion classes
  exactly.
- Canic's eventual adoption remains one atomic pre-1.0 hard cut removing its
  provider, registry, control, timer metrics, and timer-specific performance
  paths. No Canic files are changed here.
- The downstream gate requires a complete fixed inventory before first
  scheduling and owner-local authority-snapshot quiescence that cannot affect
  IcyDB or another registry owner.

## Release truth

Version 0.3.1 is tagged, pushed, and published. Historical 0.3.1 documentation
now records that completed release; this file is the open 0.3.2 release line.

## Hygiene

- Blanket dead-code allowances inherited from the implementation slices are
  removed. Pure registry constructors and accessors used only by transition
  tests are explicitly test-only; production compilation has no hidden
  dead-code warning.
- The dependency graph has no duplicate versions. The cached 1,216-advisory
  RustSec database reports no vulnerability across the 13 locked dependencies.
- Package contents are limited to the expected manifest, lockfile, README, and
  source tree. Standard MIT SPDX metadata remains the single package license
  declaration, avoiding a redundant `license-file` warning or duplicated text.
- The small repetition among policy-specific registration capabilities is
  intentional: their methods and rustdoc expose different legal operations.
  Registry effect branches remain separate atomic ownership transitions.

## Evidence

The candidate passes the normal CI gate, including 62 native tests, strict
Clippy, rustdoc, Wasm compilation, offline packaging, release-script checks,
and the private-provider boundary. Rust 1.88 workspace compilation and every
supported nested-probe lint configuration also pass.

The PocketIC watchdog matrix and policy cohorts were not rerun because this
patch changes no watchdog protocol or provider binding. The maintainer-owned
patch flow reruns that complete evidence gate before version mutation.
