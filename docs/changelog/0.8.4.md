# 0.8.4 observation and release hardening

Status: released 0.8.4.

## Changes

- Remove duplicate target-marker and status-word requirements from release
  preflight. The requested bump and changelog own target selection; the note
  still requires a matching heading and one nonempty status line. Missing notes,
  duplicate metadata, mismatched versions and canonical finalized status remain
  errors. The helper writes the released status automatically during the bump.
- Record Watchdog request observations only after schedule validation succeeds.
  An initial overflowing cadence request leaves the entire declaration snapshot
  unchanged for retained and transient lifetimes. Remove the redundant arm
  variant check from provider-effect shape validation.
- Verify hashes before executing PocketIC binaries on cached, explicit override,
  download and diagnostic paths. Preserve the pinned version/hash requirement
  and reject mismatched explicit overrides without replacement.
- Require an annotated tag under the exact `refs/tags/vX.Y.Z` name at `HEAD`.
  A branch with the same short name and a lightweight tag cannot satisfy the
  release/publication guard.
- Add a non-mutating `--check` mode to version preparation. Combined release
  targets preflight before the full deployment gate, then always perform their
  matching bump. Exact releases reject an empty `VERSION` before the gate.
- Snapshot only the six release files the bump mutates. Command failures and
  handled `INT`/`TERM` interruptions restore their original contents and modes,
  including existing user edits and both independent lockfiles. Git state and
  unrelated work are untouched. If restoration itself fails, retain the backup
  and report its location. Forced process termination or machine failure is not
  covered by these shell traps.
- Refresh the handoff and 0.8.3 release note after the user completed that
  release. Release commands, version mutation, staging and deployment validation
  remain user-owned.
- Address issue #6's documentation follow-up with cached registry provenance for
  0.8.1 and 0.8.3 and a dated Toko Miner dependency inspection. Separate earlier
  owner-reported managed qualification from the later inspected graph. Retain
  the ordered lifecycle fixture and maintained MSRV gate scope as the explicit
  disposition of advisory IC-TIMERS-003.
- Apply the two Rust-toolchain action pin changes from
  [Dependabot PR #5](https://github.com/dragginzgame/ic-timers/pull/5) at revision
  `7e38f4b43b4db5c8dd498af069a4f6196df1d067`. Toolchain versions, permissions
  and validation gates are unchanged. The PR remains open until user-owned
  delivery; no merge, commit or push is performed here.

The Watchdog observation fix affects crate behavior; other changes affect
repository tooling and documentation. No public item, signature, snapshot
shape or dependency changes. Cargo and both lockfiles remain at 0.8.3.

The undated `## [0.8.4]` changelog section is prepared with `Unreleased` empty.
The maintainer runs `make release-patch` to perform deployment validation and
the matching bump; the helper dates the section and updates release metadata.
Automated contributors have not changed package versions or lockfiles.

## Validation

Tests, build/lint gates and release commands have not been run for this work,
at the maintainer's request. Native regression coverage was added for snapshot
preservation and subsequent valid activation. New shell fixtures cover:

- branch-only, lightweight, annotated and wrong-commit release tags;
- hash mismatch, hash-read failure, version mismatch and successful binary
  verification, including automatic downloads and explicit overrides;
- release preflight preceding deployment validation, empty changelog notes,
  empty exact targets and failed deployment gates;
- prepared release-note wording with no duplicate handoff target marker,
  unchanged metadata during preflight, and rejection of missing notes, duplicate
  or empty status, wrong headings and already-finalized notes;
- failure of each root/testing lock update, each locked metadata check, final
  release truth and handled interruption, followed by byte-for-byte restoration
  and a successful retry without changes to unrelated work or Git state.

These fixtures are wired into the existing release-check gate for the user's
deployment validation. No additional recovery or performance guarantee is
claimed from unexecuted fixtures.

The feedback follow-up uses read-only lockfile, cached package VCS and consumer
ledger inspection. PR #5's recorded GitHub CI/MSRV successes belong to its earlier
branch and do not qualify this combined worktree. Issue #6's original lint changes
have the released 0.8.1 evidence recorded in its note; the accompanying documentation
corrections remain uncommitted here. Issue #7 stays open pending user-owned validation
of the existing observation regression and a released version for exact-pin consumers.
Issue #6 is closed with a
[resolution comment](https://github.com/dragginzgame/ic-timers/issues/6#issuecomment-5967615198)
that distinguishes the released lint fix from the pending documentation delivery.
