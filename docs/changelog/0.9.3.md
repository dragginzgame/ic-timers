# 0.9.3 registry validation and release metadata

Status: prepared for 0.9.3; validation and delivery are maintainer-owned.

## Registry arbitration and effect confirmation

The focused follow-up traced ordinary/Watchdog requests, completion arbitration,
provider binding, confirmation, handle cleanup and their existing native fixtures.
It found two local, behavior-preserving consolidations:

- `TimerRegistry::complete_ordinary` no longer duplicates the missing-cadence
  check already owned by `TimerDirective::resolve`. After authoritative pending
  commands select the effective directive, illegal Once recurrence resolves to
  `DirectiveError::MissingCadence`, which the existing failure mapper translates
  to `DirectiveNotAllowed`. The shared stop finalizer preserves completion work
  count, Stop observation, inactive reason and transient/retained lifetime.
  Consumer invariant failure still wins before directive resolution.
- `TimerRegistry::confirm_effect_applied` retains each effect's shape, claim,
  role and generation validation, then shares the confirmation marker, armed-delay
  observation and wakeup counter update. Dispatch alone also counts queued work.
  Both dispatch generations are validated before deduplication, so a confirmed
  successor cannot admit a different work attempt. No new state, helper layer,
  public API or compatibility path is introduced.

Existing focused fixtures include `illegal_once_recurrence_and_invariant_result_stop_truthfully`,
`exact_ordinary_reconciliation_discards_invalid_callback_proposals`,
`ordinary_terminal_failures_respect_declaration_lifetime`,
`once_coalesces_and_rotates_generations_while_nested_schedule_wins`,
`watchdog_dispatch_confirmation_rejects_cross_claim_work` and
`watchdog_dispatches_successor_first_and_retires_unacknowledged_attempt` in
[registry/tests.rs](../../crates/ic-timers/src/registry/tests.rs).
The runtime's provider-confirmation and partial-binding failure fixtures retain
their cleanup expectations. These fixtures were inspected, not executed in this
follow-up; runtime validation remains maintainer-owned.

The review deliberately retains separate ordinary and Watchdog pending commands.
Ordinary work may suspend; Watchdog work preserves a committed cadence successor
through a dispatched/running attempt. Ensure selects earliest demand while exact
reconciliation replaces proposals, so their pending forms are not equivalent.
The non-wrapping wakeup confirmation marker remains necessary to deduplicate
observations. Provider binding and confirmation remain separate: Watchdog counts
dispatch only after both handles bind, and failed partial binding has its own
cleanup/rollback boundary. No larger mechanism deletion was justified here.

## README version projection

GitHub [#3](https://github.com/dragginzgame/ic-timers/issues/3) identified a
recurring stale API label and exact dependency example in the published README.
Both now follow the current workspace version. The maintainer's bump projects
the target release into those same fields. Historical design links retain their
original subjects.

The existing workspace-version reader remains the sole version authority.
`readme-version.sh` checks or updates only the API table field and exact TOML
dependency example using that authority. The bump checks their current values
before mutation, updates them after changing the workspace version and includes
README.md in its existing rollback. Release-truth checks also validate them.
The helper does not interpret release prose or choose a target version.

Existing fixtures now cover README updates on a patch and across an API line,
stale or ambiguous fields, and restoration of README content with other metadata
after a failed bump. Commit fixtures include the structured README fields.
Shell syntax, read-only current version projection and diff whitespace were
checked. The fixtures and deployment gates remain user-owned and were not run.
