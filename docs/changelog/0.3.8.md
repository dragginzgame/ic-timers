# 0.3.8 Canic adoption evidence

Status: release candidate for 0.3.8; package version remains 0.3.7.

## Downstream evidence

- Record the validated uncommitted Canic exact-0.3.6 adoption, including the
  removed parallel provider/control/metrics runtime, fallible application timer
  facade, schema-version-2 introspection, and single-scan status/performance
  adapter.
- Preserve the distinction between owner-local ic-timers evidence and Canic's
  downstream lifecycle, inventory, protocol, host-adapter, and PocketIC timer
  evidence. Canic's maintained status reports those focused checks passing;
  this repository did not rerun them.
- Keep landing and release Canic-owned. No Canic or IcyDB file is modified by
  this patch.

## Contract corrections

- The removed global `TimerScheduled` counter was test-only, not a public
  parity surface. The maintained per-timer `schedules` field maps to committed
  `wakeups_armed`; retaining the global counter would duplicate instrumentation.
- Shared-registry initialization does not declare framework-owned work. Fleet
  Coordinator initializes an empty registry, while genuine owners reserve only
  their own fixed declarations before application hooks.
- Combined Canic+IcyDB qualification requires one exact `ic-timers` patch.
  Canic's validated worktree uses 0.3.6, released IcyDB uses 0.3.4, and IcyDB's
  validated post-tag worktree uses 0.3.5, so the present subjects cannot be
  linked as one registry.
- The release-truth checker requires one structural Canic status marker
  without freezing it to a particular adoption lifecycle state or interpreting
  its prose.

## Runtime impact

No ic-timers API, registry transition, provider behavior, snapshot shape, or
counter changes. No numerical Canic before/after benchmark is claimed.
